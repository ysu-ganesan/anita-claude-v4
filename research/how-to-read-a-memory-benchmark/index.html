How to read an AI memory benchmark

Memory

18 November 2026 / ANITA / 3 minute read

Every memory system for AI now quotes a score. Here is what the main tests measure, what they leave out, and five questions to ask any vendor, including us.

"It remembers you" is a sentence any AI product can print. A score is harder to print, which is why memory systems now quote benchmark numbers. The numbers are useful. They are also easy to misread.

This is a short guide to what the common tests measure, what they do not, and what to ask before you believe a number. That includes ours.

What the tests are

A memory benchmark gives a system a long history of conversation, then asks questions that can only be answered from that history.

LoCoMo is one of the first widely used ones. Its conversations are long on purpose: about 300 turns and 9,000 tokens each on average, spread over as many as 35 sessions. It asks questions about them, and also tests summarising events (Maharana and others, 2024).

LongMemEval has 500 questions and sorts them by the ability each one needs: pulling out a fact, reasoning across several sessions, reasoning about time, noticing that a fact has changed, and knowing when to say "I was never told that". Its authors found that commercial chat assistants and long-context models lost about 30% accuracy when they had to hold information across sustained use (Wu and others, ICLR 2025).

Leaderboards put several tests together. The Agent Memory Leaderboard, for example, runs six text benchmarks and reports seven kinds of ability, among them plain fact recall, reasoning about time and events, and two that most single tests skip: how a system governs its memory, and how it handles privacy.

What a score does not tell you

Which model answered. A memory system finds the right lines. A language model then writes the answer from them. Swap that model for a stronger one and the score rises, though the memory has not changed. Two scores are only comparable if the same model answered and the same model marked.

How much was fetched. A system that hands the model fifty lines will often beat one that hands it five. It will also cost more on every question, and it will be slower. A score with no cost beside it is half a result.

Whether the system was tuned on the test. If the people who built it adjusted it while looking at the test's own questions, the number says how well it knows the test, not how well it will know your users.

Whether it can forget. Most tests reward a system for holding on to everything. Real users say "forget that". A system that cannot do so cleanly is a problem no recall score will show you.

Whether your users talk like the test. Benchmark conversations are tidy English. Yours may be short, mixed-language and full of names. The only test that settles it is your own data.

Five questions for any memory vendor

  1. Which benchmark, and which version of it?
  2. Which model wrote the answers, and which model marked them?
  3. Was the system adjusted using the test's own questions?
  4. What happens, step by step, when a user says "forget that"?
  5. What does one stored conversation cost, what does one search cost, and how long does a search take?

A vendor who answers all five plainly is worth a trial. One who answers with a bigger number is not.

Where we stand

Nenai, our memory engine, is entered in the Agent Memory Leaderboard. Its review is not published yet, so we are not quoting a score here. When it is, we will link the result from the Nenai page, with the model that answered beside it.

We work to one rule when we measure ourselves: we test on a copy we build from the public data, and we do not tune on the questions a benchmark holds back.

And the five questions above are the ones we expect to be asked.
