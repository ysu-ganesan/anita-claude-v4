22:Td69,<p>Many welding robots are still taught the way they were decades ago. A person stands at the cell with a hand controller and walks the arm to each weld, one point at a time. While they do it, the cell makes nothing.</p>
<p>There is a better way, and it has a catch. This note explains both.</p>
<h2>Writing the program away from the robot</h2>
<p>A fabricated part already exists as a 3D model before it exists as steel. That model holds most of what a program needs: where the plates meet, where a seam could run, where the torch can and cannot reach.</p>
<p>So the program can be written from the model, at a desk, while the robot carries on working. Our welding software does this. You give it the 3D model. It finds the seams and ranks them, an operator confirms the order, and it plans the torch paths.</p>
<p>Then it tests them. A digital twin, which is a computer copy of the cell, runs every move and checks two things: can the arm reach, and does anything collide.</p>
<h2>The catch</h2>
<p>A computer copy is never exactly the real thing. A torch sits a few millimetres from where the model says. A jig has been shimmed. A plate arrives slightly bowed. Roboticists call this the gap between simulation and reality, and every team that has ignored it has a story about the day they found it.</p>
<p>So a clean run in our own software is where checking starts. It is not where it ends.</p>
<h2>Three checks before real hardware</h2>
<p>Nothing we write moves a real robot until three things are true.</p>
<p><strong>The real settings are in.</strong> A 3D model carries shapes. It does not carry weld settings. Those come from the customer&#39;s own approved weld sheet. Until they are in, the program is a sketch.</p>
<p><strong>It runs clean in the maker&#39;s simulator.</strong> Robot makers publish their own simulation software, which models their own arms and controllers better than anyone else can. The program has to run without a fault there, not only in ours.</p>
<p><strong>A person watches a dry run.</strong> The first run on the real robot is supervised, with no welding. If the arm goes somewhere it should not, a hand is on the stop button.</p>
<p>None of this is clever. It is the plain order of work that keeps a new program from costing someone a part, a day or worse.</p>
<h2>Soft things are harder</h2>
<p>Steel holds its shape. A 20 kg sack of sugar does not. It slumps, it folds, and the stack changes every time one is taken.</p>
<p>For a robot cell that empties sacks, practising in simulation means teaching the computer how a floppy sack behaves, then showing the cameras many made-up pictures of sacks before they ever see a real one. We have laid the cell out in simulation and chosen where the cameras go. Simulating the sack itself is the next piece of work, and it is not done.</p>
<h2>What to ask anyone selling you automation</h2>
<ul>
<li>Can I see the program run in the robot maker&#39;s own simulator?</li>
<li>What did you assume about my part and my settings, and where did those numbers come from?</li>
<li>Who is in the room for the first run, and is the process switched off?</li>
</ul>
<p>Anyone doing the work properly will be glad you asked.</p>
<h2>Where we are today</h2>
<p>Our welding software works end to end in computer tests on a reference part. It has not welded a real part yet. The three checks above stand between today and that day, and we will not skip one.</p>
